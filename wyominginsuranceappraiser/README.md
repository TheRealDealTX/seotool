# wyominginsuranceappraiser.com — static site

Wyoming Insurance Appraiser: a static site with no database and no plugins. A Python generator
builds it, and a small PHP front controller serves it on a Hostinger Agency Growth website.
Its engineering comes from `georgiainsuranceappraiser/` (generator, validator, deploy script,
contact handler, tool logic, photo and icon pipelines). Its content, URL scheme and design are new.

## Build, check, deploy

```sh
python3 build.py && python3 validate.py          # validate must print no ERROR lines
php -S 127.0.0.1:8765 -t public tools/qa/router.php &   # local preview with real 404s
node tools/qa/qa.js http://127.0.0.1:8765        # screenshots and layout checks
node tools/qa/tooltest.js http://127.0.0.1:8765  # tool math and drawer tests
```

Deploy:

1. Get fresh credentials from the Hostinger API call `agency-hosting_files_generate-upload-url`
   with `website_uid` set to `2qcw1GDZ3`. They expire after a few hours.
2. Run:
   ```sh
   export WYIA_FB_URL='…' WYIA_FB_AUTH='…' WYIA_FB_REST='…'
   ./deploy.sh
   ```
3. Clear the cache with `agency-hosting_cache_clear-website`.

The first deploy also deleted Hostinger's placeholder `public_html/default.php`. That was done with
`DELETE {url-without-/tus}/resources/public_html/default.php` and the same two auth headers.
`deploy.sh` only adds and overwrites files. If a page is removed or renamed, delete its old
`dir/index.php` on the server the same way. Never leave a `dir/index.html` on the server: the
host would serve it before `index.php`, skipping the guard.

To regenerate assets: run `python3 tools/photos.py` after editing `photo_sources.json`, which only
downloads new keys. Run `python3 tools/make_icons.py` and `node tools/make_og.js` to rebuild the icons
and OG image. Bump `VER` (CSS/JS) or `FAV` (icons) in `build.py` to bust caches.

## Design

- **Palette:** ember `#D4621A` (main), deep shade `#5A2408` / `#2A1206`, light tint `#FBEDE3`,
  complementary sky blue `#1F7FB6` (focus rings, small labels and accents only), and neutrals:
  basalt `#1E1B18`, stone `#F4F0EA`, line `#E5DDD2`. Buttons use dark text on ember for contrast.
- **Fonts:** Barlow Condensed (display, uppercase, highway-sign feel) + Source Sans 3 (body). No sister site uses this pairing.
- **Home order:** photo hero with a solid lead-form card and a fact ribbon; "who should you call" fork
  (A/B/C); Wyoming perils photo rail; numbered service index with a sticky intro; animated counters;
  scroll-filled timeline next to a sticky photo; ember gap-check band; dated storm-history grid;
  calculator cards; town photo grid; appraiser/PA/attorney cards; FAQ; guides; parallax CTA; contact.
- **Effects:** scroll progress bar, header that turns solid basalt on scroll (no backdrop-filter),
  Ken Burns hero zoom, staggered reveals, counters, hover zoom on photo cards, filling timeline,
  parallax CTA, back-to-top. No 3D tilt, marquee or region tabs, which sets it apart from Georgia.
  All motion respects `prefers-reduced-motion`. Without JS every section is visible, and mobile gets a
  "Menu" link to the HTML site map.
- **Mobile:** off-canvas drawer (`#drawer`) outside the fixed header, with accordion sections, scroll lock,
  and close on ×, overlay tap, link tap or Escape. It uses `inert`/`aria-hidden`, and its shadow and
  visibility apply only while open. There is a fixed two-button call bar at the bottom.
- **Logo:** a white roof gable over a dark balance beam on its fulcrum, on a burnt-orange tile. The same
  SVG is used in the header, drawer, footer and favicons. The logo link has no hover colour change.

## Photos

There are 38 photos. All are CC0 or public domain, found through the Openverse API (`license=cc0,pdm`).
They come from Wikimedia Commons, Flickr (NOAA, NPS, USDA and others), rawpixel and StockSnap. Photos
already used by sister sites were excluded, and candidates were reviewed on labelled contact sheets.
Wyoming town photos are real (Cheyenne depot, Casper, Laramie, Gillette, Green River, Riverton, Jackson,
Cody, Rawlins, Uinta County wind turbines, State Capitol). Peril photos may come from other places, and
the legal notice says so. Each photo is served as 1200px and 640px WebP with `srcset`/`sizes` and
width/height. Content images have descriptive alt text; decorative card and hero backgrounds use
`alt=""`. Everything is listed on `/photo-credits/`.

Openverse, Wikimedia and Flickr rate-limit hard. `tools/photos.py` downloads one file at a time with
backoff. Keep it that way.

## SEO rules (enforced by validate.py)

- Title ≤ 60 characters and ≤ ~580px (Arial metrics at 20px); meta description 110–150 characters; both unique
- Exactly one H1, the first heading is H1, no skipped levels (footer and sidebar headings are `<p>` or `<h2>`)
- Valid JSON-LD; every `{"@id"}` reference resolves; the graph has ProfessionalService (logo, contactPoint,
  address, areaServed, OfferCatalog), WebSite and exactly one page node with `primaryImageOfPage`,
  `mainEntity`, `isPartOf` and `breadcrumb`
- Canonical URL to `https://wyominginsuranceappraiser.com/…`, OG tags with image size and alt, Twitter card, `geo.region`
- No broken internal links or anchors; every image has `alt`, `width` and `height`
- The homepage `<main>` says "Wyoming Insurance Appraiser" at least 14 times (currently 23)
- No sister-state names anywhere in the output: Alabama, Arizona, Florida, Georgia, Missouri, Montana, Nevada, North/South Carolina, Texas

Extra schema: Service (service and town pages), FAQPage, ItemList (index pages), WebApplication
(calculators), BlogPosting (guides), HowTo (process) and DefinedTermSet (glossary).

## Hosting notes

- The host ignores `.htaccess` and has no Agency-plan "force HTTPS" setting. It serves real files
  directly (running a directory's `index.php`) and sends `/` and unknown paths to the root `index.php`.
- So every page is written as `dir/index.php` whose first line is
  `<?php require_once dirname(__DIR__, n) . '/_guard.php'; ?>`, followed by the static HTML.
  `_guard.php` 301s `www.` and plain http (from `X-Forwarded-Proto`) to `https://wyominginsuranceappraiser.com`,
  sends `X-Robots-Tag: noindex, nofollow` on any other host, and returns 404 if requested directly.
  Plain `index.html` pages were skipping this check (the host served them without PHP), so
  `http://www.…/any-page/` loaded with a 200. The root `index.php` front controller requires the
  same guard, serves `home.html` for `/`, 301s directory URLs to add the trailing slash, and returns
  `404.html` with a real 404 status. **Don't add a root `index.html`.**
- `validate.py` reads the `dir/index.php` pages, checks each starts with the guard line, and checks
  no other PHP tag appears in the page HTML.
- On `*.hostingersite.com` preview domains, Hostinger serves its own `robots.txt` that blocks Googlebot.
  The real domain serves ours. Georgia behaves the same way.

## Contact form

`/api/contact.php` has a honeypot (`website`), a per-IP rate limit (5 per 10 minutes) and validation:
it needs a name, an email or phone, and consent. It sends through `info@wyominginsuranceappraiser.com`
over authenticated SMTP (`smtp.hostinger.com:465`) when `api/_private/config.php` exists, and falls
back to PHP `mail()`. It always appends a JSON line to `api/_private/leads.log.php`, which starts with
`<?php http_response_code(404); exit; ?>`, so requesting it directly returns 404.

The SMTP password is **never committed** (`_private/` is in `.gitignore`). Hostinger's file API can't
write outside `public_html`, so the config lives in `public_html/api/_private/config.php`:

```php
<?php
if (!defined('WYIA_CONFIG_OK')) { http_response_code(404); exit; }
return ['smtp_host' => 'smtp.hostinger.com', 'smtp_port' => 465,
        'smtp_user' => 'info@wyominginsuranceappraiser.com', 'smtp_pass' => '…'];
```

Status (Nov 11, 2026): the config is uploaded, `/api/_private/config.php` returns 404 with 0 bytes,
and one submission marked TEST was logged with `"via":"smtp"` and no error. To change the password,
re-upload the file with TUS (keep a copy only outside the repo). You can read the log with
`GET {url-without-/tus}/raw/public_html/api/_private/leads.log.php` and the two auth headers.

## Google Tag Manager

`GTM_ID = "GTM-WF9LR26Z"` in `build.py`. `gtm_head()` outputs the owner's snippet exactly as supplied
(the async `gtm.js` script plus the `dataLayer`/`gtag('js', …)` block) right after `<meta charset>`.
`gtm_body()` outputs the `<noscript>` iframe right after `<body>`. Set `GTM_ID = ""` to remove both.
